# 开局托儿所自动挑战助手

macOS 本机程序，通过游戏窗口截图识别棋盘，先搜索完整消除路径，再模拟鼠标逐步执行。最高全自动实测 **159 分**，完成 74 次消除：[159 分结算截图](results/session-20261110-005453/round-113/settlement.png)。这张棋盘数字总和748，不能被10整除，因此至少剩一个数字；159已达到该棋盘的理论最高分。本次长时间挑战的逐局记录见 [会话汇总](results/session-20261110-005453/report.json)。

程序独立于 SenseUmm，不依赖 Python，不安装软件包，也不修改其 `.venv`。

## 运行一局

```sh
cd .
./build.sh
./GameAssistant selftest
./GameAssistant status
```

在微信中打开“开局托儿所”，开始一局，等数字落位后立即运行：

```sh
./GameAssistant play --target 150 --best-effort --search-seconds 32 --strategy portfolio8 --seed 7 --output runs/my-round
```

- 默认搜索预算和允许的上限均为 **32 秒**，超出上限的参数会被拒绝。`--best-effort` 会用完搜索预算，执行找到的最高分路径，即使该局规划分数低于目标也继续挑战；达到可证明的分数上限时提前结束所有搜索线程。总和能被10整除时，上限是全部剩余数字；否则至少留下一个数字。`plan.json` 保存 `scoreUpperBound` 和 `provenOptimal`，控制端独立核对。后续提高成绩应优化搜索算法或尝试新棋盘，不再增加单局搜索时间。
- 不加 `--best-effort` 时，只有验证出的路径达到目标才执行；否则保存棋盘和规划结果并停止。默认目标为 140。
- 每局可以更换 `--seed`；不同随机棋盘和搜索种子会产生不同结果。限时搜索不保证全局最优，也不保证每个棋盘都达到目标。
- 每次动作都核对所有剩余数字的已确认图像和每格纸片状态，每 10 步和最后一步重新执行完整 OCR；图像无法确认时也回退到完整 OCR。`--ocr-only` 可禁用图像快速核对。动画或暂时截图失败会重试；只有确认原棋盘完全未变时才重试拖动。
- 保持游戏在前台，不要同时移动鼠标。切换到其他应用或在终端按 Ctrl+C 可以停止。脚本总时间预算默认 120 秒，包含搜索和执行；游戏自身也在计时，所以开始一局后不要长时间停留再启动程序。

唯一游戏窗口可自动定位；存在多个同名窗口时，从 `status` 获取 ID 并传入 `--window ID`。首次运行需要给终端/宿主应用授予屏幕录制和辅助功能权限。

## 连续挑战与广告

本次长时间任务已完成三轮续期，共观看并关闭 9 段广告，每轮解锁 2 小时无限挑战：[第一次](results/session-20261110-005453/ads/renew-1794248607/unlimited-unlocked.png)、[第二次](results/session-20261110-005453/ads/renew-1794256006/unlimited-unlocked.png)、[第三次](results/session-20261110-005453/ads/renew-1794263329/unlimited-unlocked.png)。每段广告约 30 秒，出现“已获得奖励”后点击右上角“关闭”，随后核对新的无限挑战倒计时。

`play` 负责单局棋盘操作；`session` 识别结算、证书与贴纸弹窗，逐局记录后自动开始下一局。无限挑战到期时返回主界面，观看 3 段广告；每段至少等待 30 秒，且确认顶部出现“已获得奖励”和右上角“关闭”后才关闭。随后从主界面倒计时核实续期。

连续任务按 `--until` 指定的 Unix 截止时间运行，开始时游戏应停在结算或主界面。新任务使用空目录；恢复控制器时用 `--adopt-run` 指定待结算的局目录、`--start-index` 指定下一个未使用的编号。运行期间保持游戏在前台。

```sh
/usr/bin/caffeinate -di ./GameAssistant session --until "$(date -v+7H +%s)" --output runs/overnight
/usr/bin/ruby report.rb runs/overnight
```

每局目录保存初始截图与棋盘、完整规划、逐步执行日志、检查点、结算截图和实际成绩；`provenance.json` 记录种子、策略和程序 SHA-256。会话目录保存事件流水、状态、广告奖励截图和续期时间。创建 `HOLD` 文件可在局间等待，`DRAIN` 可在当前局结算后结束控制器，`STOP` 会立即停止；再次启动前移除相应文件。控制器遇到未知画面会保存截图等待人工排查，不会猜测点击。

`config.json` 中的 `strategy` 下一局生效，默认 `portfolio8`：最多 8 个计算线程在同一 32 秒预算内搜索，组合四路路径修复与四路局末搜索，最后选择最高分完整路径。两批共 12 张棋盘的同预算对照为 5 张提高、7 张持平。`plan.json` 保存各线程的得分与获胜种子。`portfolio` 保留四线程组合，也可使用单线程 `fastrepair`、`repair` 或原始 `baseline` 做对照。不要把单局未达到目标直接当作程序错误；应分别检查规划得分、执行日志和最终结算分数。

## 保存的结果与恢复

每局的 `--output` 目录包含：

| 文件 | 用途 |
| --- | --- |
| `initial-board.txt` | 初始棋盘，可离线重搜 |
| `plan.json` | 完整路径、规划得分、种子、搜索次数和耗时 |
| `checkpoint.json` | 已核对棋盘、剩余步骤、待确认动作和累计分数 |
| `latest.png` | 最近一次用于核对的窗口截图 |

程序打印的是逐步核对分数；最终成绩还应以游戏结算页为准。实测局的结算截图保存在相应目录。

中断后，如果仍是同一局且窗口尺寸未变，可以恢复：

```sh
./GameAssistant play --resume runs/my-round/checkpoint.json --output runs/my-round-resumed
```

动作在发出前写入日志状态，确认生效后再提交。恢复时会区分“动作已生效”和“动作尚未生效”，避免重复操作；遇到无法匹配的棋盘会停止。旧版仅包含数字数组的 `round.json` 不能作为新版检查点使用。

## 离线规划

```sh
./GameAssistant solve --board-file runs/my-round/initial-board.txt --target 150 --best-effort --search-seconds 32 --seed 8 --out plan.json
./GameAssistant analyze --image fixtures/board-a.png
```

棋盘文件第一行是行列数，后面按行填写数字，0 表示空格。搜索器会模拟到该路径没有合法操作为止，控制端再独立回放验证整条路径的合法性和得分。

## 布局和停止条件

默认布局基于已经验证的 704×1338 截图、16 行×10 列棋盘，并按窗口截图尺寸同比缩放。若版本或布局改变，可手动校准：

```sh
./GameAssistant capture --out game.png
./GameAssistant play --board 24,226,656,1050 --rows 16 --cols 10 --target 145 --best-effort
```

`--board` 使用截图像素，原点位于截图左上角。`click --at X,Y` 使用窗口内逻辑点，两者单位不同。

识别不完整、纸片与数字不一致、窗口移动或缩放、焦点变化、未知弹窗、权限缺失或预算耗尽，都会触发重试或停止。规则目前支持数字消除后留空、其余数字位置不变的棋盘；不支持下落、补充数字或其他新模式。微信 `#小程序://…` 分享口令的自动解析启动仍未实现。

## 代码与验证

- `Solver.cpp`：完整路径随机重启、优良路径变异、去重和退火探索。
- `Planner.swift`：调用搜索器，独立逐步回放验证所有矩形与得分。
- `GameRun.swift`：执行、复核、目标策略、动作检查点和恢复。
- `GameAssistant.swift`：窗口、权限、截图、OCR、纸片检测和鼠标操作。
- `Session.swift`：连续挑战、结算识别、广告续期和逐局留档。
- `BoardVerification.swift`：已确认数字图像与全棋盘空位核对。
- `benchmark.rb` / `report.rb`：同预算策略对照与实际成绩汇总。

`selftest` 覆盖 30 组独立动作枚举对照、非法路径拒绝、动作生效/未生效恢复、重复恢复、损坏状态拒绝、模拟棋盘 OCR，以及真实完整/稀疏棋盘回归。实际游戏成绩单独保存，不能用模拟测试分数代替。

`build.sh` 使用本机已有、与编译器兼容的 macOS 15.4 SDK；可通过 `GAME_ASSISTANT_SDK` 指定其他兼容 SDK。
